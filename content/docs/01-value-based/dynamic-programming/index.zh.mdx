> **摘要.** 三年成长的 MDP 已经写出贝尔曼方程，现在药老把它缩成一张规则完全已知的“云岚山教学棋盘”：每个格子、每种动作、每个转移概率和奖励都已列明。萧炎无需再猜环境，只需反复推演价值、改进策略。动态规划（DP）正是把贝尔曼方程变成计算步骤的方法；本章沿着“评估—改进”循环走到策略迭代，再把两者压缩成值迭代。

<Callout title="原创教学棋盘" type="info">
“云岚山教学棋盘”是教程原创的算法沙盘，并非《斗破苍穹》原著情节或地形复刻。萧炎是智能体，棋盘规则是斗气大陆环境的有限模型，药老承担模型导师与价值评估者的角色。下方实验本质仍是标准 Cliff Walking。
</Callout>

**动态规划**（Dynamic Programming, DP）是一类在有限 MDP 模型已知时计算良好或最优策略的算法。这个前提十分强：状态、动作和奖励集合有限，而且萧炎手中已有完整的一步动态 $p(s', r \mid s, a)$。因此，他不是靠亲身采样去学习未知世界，而是在药老给出的模型上规划。

现实中的斗气大陆往往未知、巨大甚至连续，所以经典 DP 作为直接求解方法有明显限制。但它像一块透明药鼎：后续方法所近似的结构——价值、自举、贝尔曼备份与策略改进——都能在这里看得最清楚。

按全书统一路线，本章来到“大斗师阶段”：先在全知模型里把贝尔曼备份练准，再与后续 MC、TD 的样本式评估对照。它不表示 DP 比其他方法战力更高；模型真的已知且状态不多时，DP 反而是应优先考虑的直接工具。

上一章定义了 $v_\pi$、$q_\pi$、$v_*$ 与 $q_*$，并写出贝尔曼最优方程：

**最优状态价值贝尔曼方程。** 它回答“可以挑选当前最佳动作时，状态的最优长期价值怎样由一步未来决定？”

$$
v_*(s) = \max_a \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_*(s')\right]
$$

**最优动作价值贝尔曼方程。** 它回答“第一步动作已固定后，环境结果与下一步最佳动作怎样共同决定其价值？”

$$
q_*(s,a) = \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma \max_{a'} q_*(s',a')\right]
$$

只要 $v_*$ 或 $q_*$ 已知，提取最优策略并不神秘：在每个状态选择相对于最优价值贪婪的动作。真正的难点是如何算出这些价值。DP 的答案是反复使用模型做一步预测，把贝尔曼等式改写成更新规则，让当前近似逐步靠近方程的不动点。

## 实验：云岚山悬崖棋盘

每次移动通常给出奖励 $-1$，表示每走一步都消耗时间；踏入悬崖给出 $-100$，并把萧炎送回起点；到达目标则结束片段。转移模型是确定性的，例如从非边缘格向右移动，下一状态完全确定。

这里的 $-1$ 与 $-100$ 是环境即时发出的**奖励**，格子的**价值**则是从该状态继续行动的期望折扣回报，两者不能混为一谈。同样，棋盘格索引在这个模型里就是完整状态；若现实中的萧炎只看到雾中一角，那只是观测，不一定足以构成马尔可夫状态。

可运行示例把掉入悬崖实现为奖励 $-100$、下一状态回到起点的转移。悬崖格仍保留在数组中以便打印，但规划轨迹不会从那里继续，因为进入它的那次转移已经重定向到了起点。

这张棋盘让规划结果可以目视检查。沿底行直冲会立刻触发悬崖惩罚；已知规则下的最优策略会比较步数代价与悬崖代价，选择能到达目标的最佳有效路线。热血并不等于闭眼冲阵：模型既然已经在手，就让每一步都经得起价值计算。

## 策略评估：药老先算当前路线

先固定一套策略 $\pi$，计算它的状态价值函数 $v_\pi$。这一步称为 **策略评估**（policy evaluation），也叫 **预测问题**：暂不改变萧炎的路线，只预测从每个格子照此行动，最终能取得多少期望回报。

贝尔曼期望方程是：

**状态价值贝尔曼期望方程。** 它回答“严格遵循当前策略时，每个状态的长期价值应该与哪些一步结果保持一致？”

$$
v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_\pi(s')\right]
$$

未知价值同时出现在等式两侧：当前格价值依赖后继格价值，后继格价值也尚未求出。有限 MDP 因而形成每个状态一个方程的联立方程组。原则上可以直接解线性方程，但动态规划选择迭代求解，因为这种更新结构会在后续强化学习算法中反复出现。

**迭代策略评估**（iterative policy evaluation）从任意近似 $v_0$ 开始，常用全零初始化。终止状态保持价值 $0$，因为终止后不再有未来奖励。第 $k+1$ 轮使用第 $k$ 轮的价值执行贝尔曼期望备份：

**同步迭代策略评估更新式。** 它回答“用上一轮整张价值表，怎样生成这一轮状态 $s$ 的新估计？”

$$
v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_k(s')\right]
$$

每次更新都把状态 $s$ 的旧估计替换为“一步期望奖励 + 折扣后继价值”。若当前近似已经等于真实 $v_\pi$，再做一次更新仍会得到同一函数，所以 $v_\pi$ 是这个贝尔曼算子的 **不动点**（fixed point）。在到达它之前，反复更新会让价值与策略、模型越来越一致。

一个两格小例子：状态甲记作 $s_A$，采取唯一动作后立即得 $1$ 并进入终止态；状态乙记作 $s_B$，得到 $0$ 并进入甲，取 $\gamma=0.9$。全零初始化时，第一轮得到 $v_1(s_A)=1,v_1(s_B)=0$；第二轮才得到 $v_2(s_B)=0+0.9\times1=0.9$。价值像斗气沿经脉一轮轮回传，并不是药老凭空把答案写进每个格子。

遍历所有状态一次称为一次 **扫描**（sweep）。价值信息会从目标附近逐轮向更远处传播，因为每个状态都借用后继状态的当前估计更新自己。这叫 **自举**（bootstrapping）：以一个估计值更新另一个估计值，而不是等一条完整轨迹结束后才使用真实回报 $G_t$。药老像沿棋盘逆推药力，每一轮只传一步，反复扫描后便能贯通全局。

## 策略改进：比较第一步的所有选择

评估回答“现有路线有多好”，改进则问“能否在某个状态换一步走法”。计算 $v_\pi$ 的价值，不只是给当前策略打分，更是为了评估一次局部偏离。

假设当前策略的 $v_\pi$ 已知。在状态 $s$ 先采取动作 $a$，随后恢复遵循 $\pi$，这次单步偏离的价值为：

**单步偏离动作价值式。** 它回答“只把第一步换成动作 $a$、之后仍照旧策略走，这次改动价值多少？”

$$
q_\pi(s,a) = \sum_{s', r} p(s', r \mid s, a) \left[r + \gamma v_\pi(s')\right]
$$

若 $q_\pi(s,a) > v_\pi(s)$，说明第一步改成 $a$、之后仍走旧路线，比从一开始就服从旧策略更好。价值函数已经总结了第一步之后的漫长未来，因此萧炎只需在当前格比较每个动作的“一步奖励 + 旧策略延续价值”。

据此构造相对于 $q_\pi$ 的贪婪策略：

**贪心策略改进式。** 它回答“依据旧策略的动作价值，新策略在状态 $s$ 应选择哪些最高值动作？”

$$
\pi'(s) = \arg\max_a q_\pi(s,a)
$$

按构造，这个新选择满足：

**单步改进不劣关系式。** 它回答“为什么贪心选择的第一步至少不低于旧策略对各动作的平均表现？”

$$
q_\pi(s, \pi'(s)) = \max_a q_\pi(s,a) \geq v_\pi(s),
$$

因为 $v_\pi(s)$ 是旧策略对同一组动作价值的加权平均。**策略改进定理**（policy improvement theorem）把局部比较提升为全局保证：

**策略改进定理结论式。** 它回答“在全部状态完成上述改进后，新策略的状态价值是否处处不低于旧策略？”

$$
v_{\pi'}(s) \geq v_\pi(s) \quad \text{for all } s
$$

本章直接使用这一定理，不展开证明。直觉上，药老并非凭感觉更换路线，而是在每个状态选出不劣于旧策略平均表现的第一步；所有状态一起这样更新，新策略便不会比旧策略差。

数字例子：旧策略在某格以各半概率选左、右，两者的 $q_\pi$ 分别为 $-4,-2$，所以 $v_\pi=-3$；新策略只选右，单步偏离值为 $-2\ge -3$。反例是只看到右移即时奖励较高便改策略，却不计算其后继价值——右边若紧接悬崖，局部即时奖励就不足以支持改进保证。

<Callout title="并列动作与随机策略" type="info">
策略评估通过 $\pi(a \mid s)$ 原生支持随机策略。改进时，为清晰起见可以选择一个最大化 $q_\pi(s,a)$ 的确定性动作；若多个动作并列最大，也可以只在这些最优动作之间分配概率，并给其余动作零概率。策略改进定理仍然成立。
</Callout>

## 策略迭代：评估一炉，改进一式

**策略迭代**（policy iteration）把两项操作交替进行：

1. **策略评估：** 为当前策略计算 $v_\pi$。
2. **策略改进：** 令策略相对于该价值函数贪婪。
3. 重复，直到策略不再变化。

当改进后策略稳定，它已经相对于自身价值函数贪婪，贝尔曼期望方程便与贝尔曼最优方程一致，所以该策略最优。对于有限 MDP，采用精确策略评估的策略迭代会在有限次策略改进后到达最优策略。

药老把这种交替称作“先看清，再出手”：评估让价值函数贴近当前策略，改进让策略对当前价值函数变得贪婪。改进后，旧价值对新策略不再精确；继续评估后，新价值又可能暴露更多可改进动作，于是两者彼此推动。

这种更一般的相互作用称为 **广义策略迭代**（generalized policy iteration）。完整策略迭代把评估与改进分成两个大阶段；后续算法会将它们交错得更紧。值迭代把改进直接折叠进每次价值更新，时序差分控制则进一步用采样转移取代完整模型扫描。

下面的交互演示使用同一悬崖行走动力学的 $4 \times 4$ 缩小棋盘：布局规则不变，但一次扫描只需 13 次备份而不是 37 次。*单步备份* 对下一个有效状态执行一次贝尔曼期望备份，*完整扫描* 在当前策略下完成一次评估扫描，*改进策略* 做一次贪婪策略改进。点击任意格子，可查看该更新对应的四个动作项。

网格显示的是一次同步快照：每轮先读取冻结的旧价值表，再统一提交全部 13 个有效状态的新值。$\gamma$ 控制保留多少未来价值，模型的阈值决定何时判定收敛。

## 值迭代：每次备份都向最优出手

完整策略迭代会在每次改进前把中间策略评估到收敛，这虽然清晰，却可能花费许多扫描，而该策略紧接着就会被替换。于是药老追问：一定要把一条暂时路线看透，才能开始改进吗？

不必。策略评估可以 **截断**（truncated）：做若干次扫描就改进策略，再继续评估。**值迭代**（value iteration）把这个思想压缩到极致，只做一次状态更新，便通过对动作取最大值把策略改进融入其中：

**值迭代贝尔曼最优更新式。** 它回答“怎样在一次备份里同时传播价值并对动作做贪心改进？”

$$
v_{k+1}(s) = \max_a \sum_{s',r} p(s', r \mid s, a) \left[r + \gamma v_k(s')\right]
$$

它与策略评估只有一个关键区别：策略评估按固定 $\pi$ 对动作取平均，值迭代用 $\max_a$ 选择当前看来最好的动作。因此，值迭代直接把贝尔曼最优方程当作更新规则。

反复扫描后，价值逼近 $v_*$，再由最终价值提取贪婪策略：

**最优贪心策略提取式。** 它回答“在已获得最优状态价值后，怎样选出使一步前瞻最大的动作？”

$$
\pi^*(s) = \arg\max_a \sum_{s',r} p(s', r \mid s, a) \left[r + \gamma v_*(s')\right]
$$

在悬崖行走这类小型有限问题中，值迭代常比“每轮都完整评估”的策略迭代使用更少总扫描，因为它不把中间策略求到高精度。在标准收敛条件下，两者最终都能得到最优价值 $v_*$，并导出最优策略；它们的差异在于评估与改进的调度方式。

若两个动作的一步前瞻都等于 $7$，$\arg\max$ 有两个答案；可以固定选一个，也可以在二者间随机化，但不能因为数组函数默认返回第一个就宣称它在数学上“唯一最优”。若近似值只差浮点误差，代码还应像本章示例一样用 `np.isclose` 判断并列。

## 为什么先在棋盘上修炼

动态规划有两道明显门槛。第一，必须知道完整模型 $p(s', r \mid s,a)$；第二，每次完整扫描都触及状态空间，当 $\mathcal{S}$ 巨大时计算无法承受。真实斗气大陆不会把全部转移规则写在卷轴上，这正是后续方法要解决的问题。

但 DP 给出了几乎所有后续基于值方法的骨架。蒙特卡洛方法会去掉模型，用完整采样回报估计价值；时序差分方法会保留自举，但只使用单个采样转移；Q-learning 会把贝尔曼最优备份用于采样得到的动作价值。

所以，这张教学棋盘不是最终战场，而是精确的表格参照：模型已知且规模足够小时，用贝尔曼备份直接求解；模型未知或太大时，再从经验中近似同一套价值传播逻辑。

> **棋盘边的小段子。** 三十轮评估在河东，一次改进到河西；莫欺第一轮全是零，价值信息还在路上。药老说完又敲了敲棋盘：“热血可以催你扫描，不能替你满足收敛条件。”这是教程原创表达，不是原著对白。

## 实现说明：把药老的卷轴写成数组

完整示例显式存储 MDP 模型。`transitions[state, action, next_state]` 保存 $p(s' \mid s,a)$，`rewards[state, action, next_state]` 保存对应转移的奖励。这样，代码可以按贝尔曼方程对每个可能的下一状态，把其概率乘以“转移奖励 + 折扣后继价值”。悬崖行走是确定性的，所以每个 `(state, action)` 只有一个下一状态的概率为 `1.0`；同一结构也能通过给多个下一状态分配概率质量来表示随机转移。

```python
transitions = np.zeros((n_states, n_actions, n_states))
rewards = np.zeros((n_states, n_actions, n_states))
action_deltas = [(-1, 0), (0, 1), (1, 0), (0, -1)]  # 上、右、下、左
```

核心计算是一步前瞻：在固定状态下，算出每个动作的期望一步奖励与折扣后继价值之和。

```python
def one_step_lookahead(
    state: int,
    values: np.ndarray,
    transitions: np.ndarray,
    rewards: np.ndarray,
    gamma: float,
) -> np.ndarray:
    """在单个状态中由一次贝尔曼备份计算动作价值。"""
    return np.sum(transitions[state] * (rewards[state] + gamma * values), axis=1)
```

策略评估按当前策略对这些动作价值取加权平均：

```python
action_values = one_step_lookahead(state, old_values, transitions, rewards, gamma)
values[state] = policy[state] @ action_values
```

值迭代复用同一组动作价值，只把策略平均替换为最大值：

```python
action_values = one_step_lookahead(state, old_values, transitions, rewards, gamma)
values[state] = np.max(action_values)
```

两个片段都采用 **同步扫描**（synchronous sweep）：先复制 `old_values`，再只用上一轮 $v_k$ 计算整张新表 $v_{k+1}$。停止阈值 $\theta$ 通过检查一次扫描中的最大价值变化实现：

```python
if np.max(np.abs(values - old_values)) < theta:
    return values, sweep + 1
```

脚本返回扫描次数，用于比较策略迭代和值迭代的计算量。示例取 $\gamma = 0.9$、$\theta = 10^{-3}$，以获得便于阅读的输出；随后把最终价值打印成 $4 \times 12$ 网格，并输出两种方法得到的贪婪策略。价值表展示奖励信息如何逆向穿过棋盘，策略表则展示规划完成后每个格子的贪婪动作。

策略改进与最终策略提取共享同一辅助逻辑：先计算全部一步动作价值，再把概率质量分给最大化动作。若有多个动作并列，代码在它们之间均匀分配概率，所以一个格子可能打印多个箭头。

```python
q_values = np.zeros((n_states, n_actions))
policy = np.zeros((n_states, n_actions))

for state in range(n_states):
    q_values[state] = one_step_lookahead(state, values, transitions, rewards, gamma)
    best_value = q_values[state].max()
    best_actions = np.flatnonzero(np.isclose(q_values[state], best_value))
    policy[state, best_actions] = 1.0 / len(best_actions)
```

完整均匀扫描不是唯一调度。异步动态规划会就地更新状态，因此同一遍后面的状态可以利用刚刚更新的新价值。只要每个状态被足够频繁地更新，异步方法仍可收敛。当部分状态更重要时，计算还可以集中到最相关区域；本章不展开优先级扫描，只需记住贝尔曼备份不必永远整齐地逐表扫描。

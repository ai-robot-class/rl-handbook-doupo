> “三十年河东，三十年河西，莫欺少年穷！”

故事从乌坦城的一段低谷开始。萧炎曾经锋芒毕露，却在环境变化后失去了原有优势。若只看眼前的状态，他似乎已经走进绝境；但强化学习关心的从来不只是一次得失，而是一个行动如何改变后续状态，以及一连串选择最终能带来多少长期回报。

这正是本手册想带你理解的问题：当世界充满不确定性、每次行动都会影响未来时，一个智能体应当如何从交互中学习，并逐步形成更好的策略？在我们的叙事类比里，萧炎是智能体，斗气大陆是环境，修炼、历练与抉择是动作，境界与任务局面构成状态，而战斗结果、资源收获和长期成长则提供奖励信号。环境不会因为主角一时失意就永远停在原处；状态之间存在转移的可能，策略也能随着经验不断改进。

直到药老出现，散乱的试错才开始变成有方向的修炼。药老并不是替萧炎作出所有决定，也不能保证每一步都得到最高的即时奖励。他更像一套帮助智能体评估长期价值、平衡探索与利用、不断修正策略的学习机制：指出哪些经验值得保留，哪些选择看似吃亏却可能通向更高的未来回报。真正执行动作、承受结果并从轨迹中学习的，仍然是萧炎自己。

这些人物与情节只承担建立直觉的作用。后续章节会把类比还原为严格的数学对象、算法步骤和可运行代码；故事不能替代定义，热血也不能替代验证。我们的目标，是让直觉像异火一样点亮方向，再用公式与实验把每一步修炼落到实处。

为了让长路不显得虚无，我们会把学习进度借作一条“境界刻度”：**斗之气**先认清智能体、状态、动作与奖励，**斗者**练习赌博机中的探索—利用，**斗师**理解 MDP、回报与贝尔曼方程，**大斗师**比较动态规划、MC 与 TD，**斗灵**进入 Sarsa、Q-learning 与 DQN 控制，**斗王**学习策略梯度、Actor-Critic 与 GAE，**斗皇**复用旧经验完成连续控制，**斗宗**借模型规划未来，**斗尊**处理离线、多目标与多智能体设定，**斗圣**审视模型偏差、分布偏移与奖励漏洞。最高的“斗帝”不对应某个算法，而是能根据任务、数据和风险选择并验证方法。

这条刻度只表示**本教程的知识递进**，绝不是算法强弱排行榜。一个表格型 Q-learning 在合适的小环境里可以比深度网络更稳、更快、更容易验证；一个被称为“斗圣级”的复杂模型若假设错误，也会在真实环境里输给朴素基线。境界高不等于名字响，真正的“破境”是能说清问题、假设与证据。

> **乌坦城小剧场。** 有人笑萧炎只会手算四格棋盘，他把笔一放：“三十轮探索在东，三十轮评估在西；今日一格一格算，明日才能不被一张漂亮损失曲线骗穷。”这是教程原创段子，不是原著对白；热血可以助记，结论仍要靠实验。

## 这本手册要修炼什么

本手册提供一条从基础概念通往现代强化学习方法的连贯路径。你会同时接触三种互相支撑的内容：

- **直觉。** 用萧炎的选择、药老的引导和斗气大陆的变化理解状态、动作、奖励、回报、策略与价值。
- **数学。** 用马尔可夫决策过程、贝尔曼方程和优化目标精确定义问题，明确算法成立所需的假设。
- **实践。** 通过代码与实验观察智能体如何收集经验、更新估计，并在训练中变得更强。

它既适合第一次踏入强化学习领域的学习者，也可以作为研究者和工程师查阅特定主题的参考。手册是开源且持续更新的：章节会补充，解释会修正，示例也会随着社区反馈不断完善。修炼没有一劳永逸的终点，知识同样如此。

同一个概念会反复从不同角度出现。例如，“奖励”和“回报”会先用两个小例子分开：一场战斗立刻获得 $+5$ 是奖励；此后连续得到 $+5,-2,+10$，按折扣汇总后才是回报。又如，“状态”和“观测”也不能混用：完整的境界、伤势、位置和敌情可以构成状态；萧炎只看见眼前烟尘，则只是部分观测。先把这些容易混淆的概念拆开，后面的公式才不会变成只会背诵的功法口诀。

## 入门三章：从立志到认路

引言部分由三个连续的落脚点组成：

1. **引言。** 也就是你正在阅读的这一页。它说明这趟旅程的目标、叙事方式和学习边界，相当于萧炎在低谷中重新确认自己为何出发。
2. **什么是强化学习？** 下一章正式建立智能体—环境交互循环，解释状态、动作、奖励、回报与策略。你会看到，一次选择如何通过环境的转移影响下一刻，以及为什么长期回报比一时胜负更重要。
3. **RL 方法分类。** 第三章给出整片领域的地图，区分基于值与基于策略、同策略与异策略、无模型与基于模型等路线。它就像药老摊开修炼卷轴：不同功法解决不同问题，没有一种算法可以包打天下。

如果你已经熟悉这些概念，可以直接进入“基于值的方法”，从多臂赌博机、马尔可夫决策过程和动态规划开始技术修炼。不过，即使已有基础，先浏览方法分类也能帮助你理解全书为何采用现在的章节顺序。

## 阅读、提问与共同完善

每章标题附近提供两个实用控件：

- `复制 Markdown` 会复制当前章节的源文本。你可以把它交给语言模型，请它解释某段推导、比较两个算法，或逐行分析代码。模型的回答仍可能出错，请回到公式、代码和实验结果中核验。
- `反馈` 会打开该章节对应的 GitHub issue。若你发现概念错误、公式问题、代码缺陷、翻译偏差或不恰当的故事类比，欢迎在那里提出；清楚描述问题并附上位置，会让修正更高效。

贡献不必是一门“天阶斗技”。一个错别字、一句更准确的解释、一个能复现的反例，都会让后来者少走弯路。若你愿意提交修改，请尽量保持数学含义、术语与代码行为一致，并说明改变背后的理由。

## 关于中文版本

本手册以英文内容作为技术基线，同时提供中文版本以降低阅读门槛。中文叙事加入了《斗破苍穹》式的人物映射与修炼主线，但强化学习术语、公式和算法目标应与英文技术内容保持一致。

翻译与改写可能滞后，也可能在术语选择或故事类比中出现偏差。遇到疑问时，可以切换到英文页面对照原意；若两种语言不一致，请优先核对定义、论文与代码，并通过反馈入口告诉我们。药老能指路，却不能替任何人完成修炼；这本手册也一样——它提供地图与方法，真正建立理解的，是你一次次推导、实现和验证的过程。
